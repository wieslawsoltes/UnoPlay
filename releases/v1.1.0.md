UnoPlay 1.1.0 adds Spotify account authorization, the official Web Playback SDK, Spotify Connect controls, and playlist management to the classic-skinned player. [Open UnoPlay in the browser](https://wieslawsoltes.github.io/UnoPlay/).

## Spotify

- Open **Options → Spotify** or press **Alt+S**. Sign in through Spotify using Authorization Code with PKCE S256 and automatic token refresh.
- Play through the official SDK in a supported browser, or select an available Spotify Connect device from the browser or desktop app.
- Browse paginated playlists, liked songs, album tracks, and the playback queue. Search tracks, playlists, albums, and artists, or open Spotify links and URIs.
- Create playlists, edit their details and JPEG covers, add tracks and episodes, reorder items, remove items, and save or remove library entries.
- Control playback, seeking, volume, shuffle, and repeat from the Spotify window and the classic transport. Switching to local media restores UnoPlay's local media controls.
- Reuse `UnoPlay.Spotify` for portable authorization and Web API access, and `UnoPlay.Spotify.Uno` for the SDK bridge and platform authorization flows.

## Account setup

Enter your Spotify developer app's public Client ID in the Spotify window. Shared builds can embed a default using the repository Actions variable `SPOTIFY_CLIENT_ID` or the MSBuild property `SpotifyClientId`.

Register the redirect addresses used by your build.

| App | Redirect URI |
| --- | --- |
| Published browser app | `https://wieslawsoltes.github.io/UnoPlay/` |
| Desktop app | `http://127.0.0.1/spotify/callback` |

The desktop callback listener chooses an available port for each authorization. The browser's **Setup instructions** button shows its exact redirect address.

Spotify playback requires Premium. Development-mode apps require a Premium app owner and allowlisted users. Desktop playback uses the selected Spotify Connect device. Browser playback uses the official SDK and requires encrypted-media support. [Spotify SDK requirements](https://developer.spotify.com/documentation/web-playback-sdk/tutorials/getting-started) · [Quota modes](https://developer.spotify.com/documentation/web-api/concepts/quota-modes)

## Verification

Automated checks cover portable Spotify authorization and Web API behavior, real desktop loopback callback sockets, the SDK bridge, and the published Uno browser UI. Spotify UI tests use explicit API and SDK fixtures, including PKCE validation, token refresh, playlist pagination, playback, sign-out, rejected callbacks, and return to local playback. Existing real MP3, MP4, streaming, DSP, and skin tests remain in the publishing pipeline.

Live account authorization and Spotify audio playback still require verification with a registered client ID and an eligible account.
