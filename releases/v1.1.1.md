UnoPlay 1.1.1 completes two edge-case fixes found while reviewing the Spotify integration. It includes the Spotify authorization, Web Playback SDK, Connect playback, playlist editing, search, and reusable libraries introduced in [v1.1.0](https://github.com/wieslawsoltes/UnoPlay/releases/tag/v1.1.0).

- Reorder every entry in an editable Spotify playlist, including local recordings and unavailable items. Moves preserve absolute positions and use playlist snapshots.
- Closing MiniBrowser through its menu stops the embedded page and restores main-player keyboard shortcuts.
- Browser regressions exercise both close paths, restored play/pause shortcuts, and reordering local and unavailable Spotify entries.

[Open UnoPlay in the browser](https://wieslawsoltes.github.io/UnoPlay/).

## Spotify setup

Open **Options → Spotify** or press **Alt+S**, enter your Spotify developer app's public Client ID, and sign in. Shared builds can embed the Client ID using the `SPOTIFY_CLIENT_ID` repository Actions variable. Register `https://wieslawsoltes.github.io/UnoPlay/` for the published browser app and `http://127.0.0.1/spotify/callback` for desktop authorization. [Setup and platform requirements](https://github.com/wieslawsoltes/UnoPlay#spotify)

Browser playback uses the official Spotify Web Playback SDK. Desktop playback uses a selected Spotify Connect device. Spotify playback requires Premium, and development-mode apps require allowlisted users. Live account authorization and Spotify audio playback still require verification with a registered client ID and an eligible account. Automated Spotify checks use explicit API and SDK fixtures.
